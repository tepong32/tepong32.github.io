The problem

File synchronization should not require blind trust

In shared-file environments, a copy can replace newer work or move files in the wrong direction. TraceSync compares first, shows differences, requires a direction, previews exact changes, and asks for confirmation.

The office situation behind it

Two folders, one question: which copy is actually newer?

That is a small question until the files are payroll, reports, or shared records. TraceSync grew from treating that uncertainty as a product problem. Instead of making the copy button faster, I made the decision before the copy easier to inspect.

Engineering decisions

Safety controls built into the workflow

Explicit direction

One-way synchronization avoids ambiguous conflict resolution and makes user intent inspectable.

Immutable preview contract

Only reviewed, eligible files enter a job; per-file selection preserves operator control.

Pre-copy revalidation

Source and destination metadata are checked again immediately before each copy.

Accurate failure records

Execution results remain truthful even when final history persistence fails.

Architecture

UI and filesystem behavior remain separated

MainWindow │ SyncService ├── StorageScanner ──► StorageProvider ├── comparer ────────► ComparisonResult └── SyncPreview ─────► SyncJobRunner ──► SyncJob

Verification

Tests and failure handling

Regression suite

Coverage spans comparison confidence, Folder Pairs, preview selection, copy safety, settings, UI behavior, persistence, export, and history recovery.

Structured run records

Versioned JSON records use validated identities, interrupted-run recovery, and bounded retention.

CSV export safety

Export protects spreadsheet users against formula injection and includes only the selected run.

Single active job

A per-user operating-system lock prevents overlapping synchronization jobs without claiming distributed locking.
